## 作品名

AIだけじゃダメですか？！（リポジトリ名・プラグイン名: pdcaai）

## 一言

大AI開発時代、人間は指示を出すだけでいいの？ 先に自分で考え、AI社員4人と突き合わせて、自分で気づける範囲を広げる Claude Code プラグイン。

## 概要（案）

pdcaaiは、Claude Code で「これで作って」「完成」と言った瞬間に動くプラグインです。

1. フックが一度だけ「先に気になる点を1つ挙げてみますか？」と声をかける。
2. 本人が先に、思いつく検討事項を一言ずつ出す。
3. AI社員4人（新入社員、法務・リスク管理、財務、ユーザー）がサブエージェントとして並列に、本人の答えを見ずに洗い出す。
4. 突き合わせて、自分で出せたもの、AI社員だけが気づいたもの、自分だけが気づいたものに分け、観点帳に積む。
5. 次の周回では、見落としやすい観点だけにヒント（補助輪）が付き、自分で出せるようになった観点からヒントが外れる。

観点帳は一本の木として描かれ、周回ごとに上へ伸びます。

## 出発点

- 同人誌の入稿PDFツール「RakuNovel」のテスト版を公開したとき、タイトル欄に長い文字列を入れると途中で崩れるなど、自分では想定していなかった不具合を利用者に指摘された。
- 指示を受けて「わかりました」と先走り、意図とずれて作ってしまうことがある。思い込みは気をつけても減らない。
- 一人で事業を回しているので、「引継ぎにこれを入れないと」を考える相手がいない。

- 作者は自分で絵を描く。イラストやデザイン、音楽までAIで全部まかなえる時代に、人間が考えたり作ったりする力が細っていくことに危機感がある。

AIに全部出してもらえば済む、とは考えませんでした。毎回AIに頼るだけでは、次も同じところで止まるからです。

## 作ってみて分かったこと

自分で3周回してみて、ほかの人が使うときに何を入れておくべきかを自分で思いつくのは、思っていたよりずっと大変だと分かった。【要確認: 本人の言葉で書き直す】

自分にスキルのある題材で回したとき、自信は70%から80%に上がったのに、手応えは下がった（-1）。作者の言葉:

> 「AIがいるしいいか…だとAIででない思想がでてこない。」

## 人間の伸び（作者本人の記録）

作者が「自分の開発を外部に委託するマニュアル」を題材に3周回した記録です。

| 周回 | ヒントなしで自分で | ヒントで追いついた | 自分だけ | ヒントで広がった | 自信 |
|---|---|---|---|---|---|
| 1 | 0/12 | 0 | 4 | 0 | 50→60% |
| 2 | 0/12 | 4 | 6 | 1 | 60→68% |
| 3 | 1/11 | 2 | 2 | 3 | 68→75% |

- 3周目にヒントの前に書いた3つ（セキュリティ、秘密キー、問題が起きたときの報告ルール）は、いずれも前の周回で見落とした型に当たっていた。判定はClaudeが行い、本人が同意した。
- 3周とも、AI社員4人が誰も出さなかったことを本人が出した（似たサービスとの比較、相手との相性、フォントや色の指定、お金をかけたくない事情など）。

3周、1人だけの記録なので、効果の実証ではありません。

## 思考の広がり

ヒントは「AIに追いつく」より「自分の考えを広げる」ほうに効きました。

- 本人: ヒントのあとに、AI社員も出していない考えが1周目0件、2周目1件、3周目3件出た（作業前のバックアップ、古いバックアップがたまる費用、返金を相談に回すケースなど）。
- 試験走行: 架空のペルソナ5人×4周でも、ヒントのあとにAIも出さなかった考えが1人1周あたり約1.5件出た（`docs/SIMULATION.md`）。

## Claudeの活用

| 使ったもの | 目的 |
|---|---|
| フック（UserPromptSubmit） | 「これで作って」「完成」の瞬間を捕まえる。1セッション1回だけ、止めずに声をかける |
| スキル | 本人が先、AIが後という順番を守らせる |
| サブエージェント4人（Sonnet） | 観点ごとに並列で、本人の答えを見ずに独立して洗い出す。速さを優先して軽いモデルにした |
| 突き合わせ（スキルを動かしているClaude） | 本人の答えからの一字一句の引用と、題材に依存しない「型」を付ける |
| スクリプト（AIを使わない） | 引用が実在するか、前に見落とした型と一致するかをコードで確かめ、ヒントの強さを計算する |
| `claude -p` の構造化出力 | 架空のペルソナとAI社員を自動で回す試験走行 |
| Claude Code | 設計、実装、テスト、調査、レビューのすべて |

## 試行錯誤の経緯

1. 最初はフォームに答えていく形 → 作者自身が試して「考えさせられるのがきつい」 → 会話の形に作り直した。
2. 会話の形 → 「普通にClaudeと話すのと変わらない」 → 実物と予想を比べる方向を検討した。
3. 似たスキルを調べた → プレモーテムや問い返し型のスキルはすでに多い → 「AIが毎回出して終わり」ではなく、人間が自分で出せるようになったかを測る方向に絞った。
4. ヒントが前の題材の言葉のままで分かりにくい → 題材に依存しない「型」で出すようにした。
5. 同じ題材の2周目で重複がいや → 前回までの項目をAI社員に渡して避けさせた。
6. 試験走行で、項目の一致だけでは伸びが測れないと分かった → 「前に見落とした型を自分で出せたか」を数えるようにした。

## 正直に書く限界

- 効果の実証はしていない。作者1人の3周と、AIのペルソナによる試験走行だけ。
- 「同じ論点か」「前に見落とした型に当たるか」の判定はClaudeが行う。引用が本人の答えに実在するかと、型が過去の記録に実在するかはコードで確かめるが、論点が同じかどうかの判断そのものは検証していない。
- 試験走行では、振り返りの記憶ありとなしで差が出なかった。ペルソナはAIなので、人間の伸びの代わりにはならない。
