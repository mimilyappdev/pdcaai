## 作品名

AIだけじゃダメですか？！（ツール名: PDCAI／リポジトリ名・プラグイン名: pdcaai）

## 一言

AIに引継ぎマニュアルを作らせると、見た目はきれいでも後任が止まる。PDCAIは、人が先に書き、AI社員4人が「書かれていない所」を指し、後任役のAIが実際に止まった場所を返す。人の頭の中にある、言語化されていない判断を掘り出す Claude Code プラグインとWebアプリ。

## ゴール

1. いまある仕事や新しく検討していることを、他の人やAIに引き継ぐときにマニュアルを作る。
2. AIに依存せず、AIと共生しながら、人の思考力・想像力・創造力を伸ばす。ここでいう思考力は、主に「言語化されていない判断を考える力」。

## 普通にAIに相談するのと何が違うか

- AIは書かない。人が書いた文に「足りない所」を指し、後任役として「ここで止まった」と返すだけ。カードに残るのは本人の言葉だけ。
- AIが作った資料から始めてもよい。①に貼れば、抜けを自分で考えて書き足せる。架空のカフェでは、AIだけのマニュアル（8場面中5つで止まった）に人が書き足すたびに止まる数が減り、最後は0になった（最後の決めごとは店長役のAI）。
- 人が先に出す。AI社員は本人の答えを見ずに洗い出し、あとで突き合わせる。
- 伸びを測る。前に見落とした型を、次の周回でヒントなしに自分で出せたか（再会カード）を数える。

## 概要

PDCAIは、Claude Code で「これで作って」「完成」と言った瞬間に動くプラグインです。

1. フックが一度だけ「先に気になる点を1つ挙げてみますか？」と声をかける。
2. 本人が先に、思いつく検討事項を一言ずつ出す。
3. AI社員4人（新入社員、法務・リスク管理、財務、ユーザー）がサブエージェントとして並列に、本人の答えを見ずに洗い出す。
4. 突き合わせて、自分で出せたもの、AI社員だけが気づいたもの、自分だけが気づいたものに分け、観点帳に積む。
5. 次の周回では、見落としやすい観点だけにヒント（補助輪）が付き、自分で出せるようになった観点からヒントが外れる。
6. 本人の言葉だけで1枚の引継ぎカードを作る。
7. 後任役のAIがカードだけを読んで、よくある場面をやってみる。止まった場所と「足りない1行」を返す。本人が1行足し、止まった数が0になるまで繰り返す。初めての場面も混ぜる。

観点帳は一本の木として描かれ、周回ごとに上へ伸びます。周回を並べた「伸び」の表と、再会カードで見返せます。

## 出発点

- 同人誌の入稿PDFツール「RakuNovel」のテスト版を公開したとき、タイトル欄に長い文字列を入れると途中で崩れるなど、自分では想定していなかった不具合を利用者に指摘された。
- 指示を受けて「わかりました」と先走り、意図とずれて作ってしまうことがある。思い込みは気をつけても減らない。
- 一人で事業を回しているので、「引継ぎにこれを入れないと」を考える相手がいない。
- 作者は自分で絵を描く。イラストやデザイン、音楽までAIで全部まかなえる時代に、人間が考えたり作ったりする力が細っていくことに危機感がある。

AIに全部出してもらえば済む、とは考えませんでした。毎回AIに頼るだけでは、次も同じところで止まるからです。

## 引継ぎで分かったこと（一般的な業務1つで3周）

題材は、会社でよくある「請求書の未払いを、営業がお客さんに確認する」業務。作者が先輩役として、後輩が迷わないように引継ぎを書いた。

### AIだけのマニュアルと、AIと3周回したカード（同じ10場面）

| | 後任AIテストで止まった数 |
|---|---|
| 作者の最初のメモ9行から、AIに普通にマニュアルを作らせた | 6 / 10 |
| PDCAIで3周回した、作者の言葉だけのカード | 0 / 10 |

- AIのマニュアルは手順番号と例文つきで、見た目は整っていた。止まったのは、メモの外の場面（まとめて振り込まれた、多く振り込まれた、社名が変わった、など）。AIは、本人が言葉にしていない判断を足せない。
- 同じClaudeでも、書き手として使うか、読んで止まる試験官として使うかで、6/10 と 0/10 に分かれた。
- 公平さについて: 10場面のうち9つは、周回の中で出てきた場面。初めて見る場面（取引先が合併して社名が変わった）では、カードも最初は止まった（1/10）。作者が1行足して通った。

### 後任役を5つのAIに替えても同じか（同じ15場面）

10場面に、記録を一切見ていない係が作った初めての5場面を足し、後任役のAIを替えて試した。

| 後任役 | AIだけのマニュアル | PDCAIのカード |
|---|---|---|
| Claude Opus | 6/10 ・ 4/5 | 0/10 ・ 2/5 |
| Claude Sonnet | 7/10 ・ 4/5 | 0/10 ・ 3/5 |
| Claude Haiku | 9/10 ・ 5/5 | 3/10 ・ 3/5 |
| ChatGPT | 8/10 ・ 4/5 | 1/10 ・ 4/5 |
| Gemini | 7/10 ・ 4/5 | 0/10 ・ 3/5 |
| 合計（止まった回数） | 58 / 75 | 19 / 75 |

- どのAIが後任をやっても、本人の言葉のカードの方が止まらなかった。特定のモデルに合わせた結果ではない。
- 初めての5場面では差が小さい（21/25 → 15/25）。カードは本人が答えた場面までしか効かない。だから次は、何人もの担当者が「このケースは？」に1行ずつ答えるケース集が要る。
- ChatGPT・Gemini は、作者が各サービスに同じ指示と資料を貼って試した。

### 人の伸び（同じ題材の3周）

| 周回 | 何をしたか | 前に見落とした型を、ヒントなしで出せた | ヒントのあとに広がった、自分だけの考え |
|---|---|---|---|
| 1 | 作者が先に書いた | - | 0 |
| 2 | 初めての場面を先に見てから書いた（ヒントで考えた周） | 0 / 6 | 7 |
| 3 | 何も見せずに書いた | 4 / 17 | 0 |

- 3周目は、1〜2周目にAI社員だけが出した型（記録のない口約束、仕事の起点、相手の落ち度と決めつける書き出し、証拠が個人のメールに閉じている）に、作者が自分の言葉で再会した。
- 2周目は、先に場面を見せたので「自分で出せた」に数えていない。
- 作者の感想【要確認: 引用してよいか】:
  > 「実際の業務でやれるかは別として、人間の言語化してないもののマニュアルって結構でかいよ」
  > 「頭にあるものを全部言語化できるとは限らない、なので引き継ぎツールを使ったら出るわ出るわのケースが多い。」

## Claudeの活用

| 使ったもの | 目的 |
|---|---|
| フック（UserPromptSubmit） | 「これで作って」「完成」の瞬間を捕まえる。1セッション1回だけ、止めずに声をかける |
| スキル | 本人が先、AIが後という順番を守らせる |
| サブエージェント4人（Sonnet） | 観点ごとに並列で、本人の答えを見ずに独立して洗い出す。4人を同時に動かすので、速さを優先して Sonnet にした |
| 突き合わせ（スキルを動かしているClaude） | 本人の答えからの一字一句の引用と、題材に依存しない「型」を付ける |
| 後任AIテスト（`claude -p` の構造化出力、Opus） | Claudeを書き手でなく試験官として使う。書かれていないことを推測で補わない厳密さが要るので Opus にした【要確認: 選んだ理由は本人と確認】。軽い Haiku の後任では止まる数が増える（新人ほどAIだけのマニュアルでは動けない、の近似）。カードだけで判断し、推測で補わず、止まった行を引用で返す。場面は1回目に固定し、止まった数を比べる。初めての場面も作らせる |
| スクリプト（AIを使わない） | 引用が実在するか、前に見落とした型と一致するかをコードで確かめ、ヒントの強さと伸びの分母を計算する |
| Claude Code | 設計、実装、テスト、競合調査、辛口の審査役、レビューのすべて |

Claude Code があったから、作者一人で6日の間に、設計・実装・テスト33件・競合調査・辛口審査・ペルソナでの試験走行・5つのAIでの比較まで回せた。後任テストは1回およそ30秒〜1分。人の新人に毎回試してもらうのは、現実には無理。

## 試行錯誤の経緯

1. 最初はフォームに答えていく形 → 作者自身が試して「考えさせられるのがきつい」 → 会話の形に作り直した。
2. 会話の形 → 「普通にClaudeと話すのと変わらない」 → 実物と予想を比べる方向を検討した。
3. 似たスキルを調べた → プレモーテムや問い返し型のスキルはすでに多い → 「AIが毎回出して終わり」ではなく、人間が自分で出せるようになったかを測る方向に絞った。
4. ヒントが前の題材の言葉のままで分かりにくい → 題材に依存しない「型」で出すようにした。
5. 試験走行で、項目の一致だけでは伸びが測れないと分かった → 「前に見落とした型を自分で出せたか」を数えるようにした。
6. 自分で回して「引継ぎアプリとして使えている」と気づいた → 引継ぎカードと後任AIテストを足した。
7. AI社員の「新入社員」と「引き継ぐ相手」が重なった → 「新入社員が分かれば誰でも分かる」とまとめ、4人目を受け取る側の「ユーザー」にした。
8. 伸びの数字に分母がなかった → 「前に見落とした型のうち何個」で見せ、再会カードを作った。

## 正直に書く限界

- 効果の実証はしていない。作者1人の周回と、AIのペルソナによる試験走行だけ。
- 後任AIテストの場面の多くは周回の中で出てきたもの。初めての場面での検証は1場面だけ。
- 「同じ論点か」「前に見落とした型に当たるか」の判定はClaudeが行う。引用と型が記録に実在するかはコードで確かめるが、論点が同じかどうかの判断そのものは検証していない。
- 後任役はAIで、人間の新人が同じように動けるかは確かめていない。

## これから

作者自身が、締切後もブラウザだけで動く形にして使い続ける予定。

1. 引継ぎに使う（自分の事業の外注や、人に任せる仕事）
2. 新規事業の検討に使う
3. 自分の思考を広げたり、前に考えたことに戻ったりするのに使う

ほかに考えていること:

- 何人もの担当者が「このケースは？」に1行ずつ答える、ケース集（集合知）。
- 見えにくい強み（丁寧に引継ぎを書く人）を見つける使い方。
